# 伊甸工程 · 物品提交池（静态配置）

## 配置文件在哪

```
D:\.minecraft\versions\new project\config\maixr\eden_pool.json
```

**这就是唯一数据源** —— 池子里有什么、每个要几个，全由这个文件决定。
代码**不再**从配方表推算。

> jar 里也内置了一份同名文件（`config/maixr/eden_pool.json`）作为出厂默认。
> **游戏目录下那份优先** —— 只要它存在，就用它。

---

## 怎么改

### 改数量
直接把数字改掉：

```json
"minecraft:stone": 16   →   "minecraft:stone": 64
```

### 移出池子
删掉那一行即可。

### 加进池子
复制一行改成你要的 ID（**记得放对阶段**）：

```json
"mymod:my_item": 8
```

### 改阶段名
```json
{ "name": "残响", "items": { ... } }
```

### 加减阶段
在 `stages` 数组里增删一个 `{}` 块。
**阶段顺序 = 进度顺序**：第一个对应 0%~10%，最后一个对应 90%~100%。

---

## 完整格式

```json
{
  "defaultCount": 16,
  "stages": [
    {
      "name": "残响",
      "items": {
        "minecraft:stone": 16,
        "ae2:blank_pattern": 8,
        "maixr:soul_gem": 4
      }
    },
    { "name": "篝火", "items": { ... } }
  ]
}
```

| 字段 | 说明 |
|---|---|
| `defaultCount` | 没写数量的物品用它（默认 16） |
| `stages[].name` | 阶段名（显示在聊天栏提示里） |
| `stages[].items` | 物品 ID → 需求数量 |

---

## 抽取权重（代码里固定，不在配置里）

点名时按玩家**当前进度**所处的阶段加权：

| 距离当前阶段 | 权重 |
|---|---|
| 本阶段 | **×8** |
| 相邻阶段 | **×3** |
| 其余 | ×1 |

所以前期不会撞上终局产物，后期也不会被石头烦。

---

## 改完怎么生效

**不用重启游戏**，在游戏里敲：

```
/reload
```

代码挂在 `OnDatapackSyncEvent` 上，重载数据包时会重新读配置。
日志里会打印：

```
[伊甸] 提交池已随数据包重载：10 个阶段 / 4381 种物品
```

## 没装的模组会怎样

配置里如果写了**当前没装**的模组物品，加载时**静默跳过**（不刷屏），
日志里汇总一行：

```
[伊甸] 提交池已加载：10 个阶段，共 4381 种物品（跳过 12 个未安装模组的物品）
```

所以你可以**提前**把以后要装的模组物品写进去，装上就自动生效。

## 排查

| 症状 | 查什么 |
|---|---|
| 池子不生效 | 日志搜 `[伊甸] 提交池`；配置缺失时会报 `[伊甸] 读取提交池失败：...` |
| 某物品一直不出现 | 它的模组装了没；ID 拼对了没（用 `F3+H` 开高级提示看物品 ID） |
| 数量不对 | 配置里那个数字；没写就是 `defaultCount` |
| 改完没反应 | 敲 `/reload`；或看日志有没有 `提交池已随数据包重载` |
| 想导出现状对照 | 游戏里跑 `/maixr edenpool`（会写 `logs/maixr_eden_pool.txt`） |

## 历史

早期版本是**动态池**：遍历全部配方、递归算复杂度（`computeCost`）、
按分位数切十段。问题：

- 启动慢（要递归遍历上万条配方）
- 偶尔算错（配方成环、深度上限 40）
- 换了模组结果会漂移

**现改为静态配置**，完全可控。旧实现备份在
`D:\cfpatch\backups\eden_dynamic_pool\EdenCoreBlock.java`。
