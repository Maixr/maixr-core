> **注**：本文中与「伊甸修复」相关的章节（取样源 pristine / 重生世界 reborn /
> 修复引擎等）所述系统**已从本模组整体移除**，内容仅作历史参考。


> **一句话**：选了「破碎」，**主世界本身就是破碎世界** ——
> 逐方块**碎裂场**：全图统一碎裂水平（原四带渐变与平静区已取消），
> 地形被裂缝网络与板块漂移逐方块撕碎；碎裂场仅作用于主世界
> （下界/末地为原版生成）。出生点由 `BrokenSpawnSearch` 接管（三级搜索，见「一点八」）。
>
> **★ 地形与结构完全解耦**：地形由密度管线内的碎裂场撕碎，
> 而结构（村庄/要塞/末地传送门）在无地形区域**照常完整落地** —— 悬空的残存遗迹。

## 一、碎裂场（v2.0 重写：`maixr:fracture` / `maixr:plate_field` / `maixr:plate_displace`）

> ⚠️ **历史注记**：本章节原为「渐变虚空」（区块级哈希二值判定：区块要么 100% 地形
> 要么 100% 空，洞沿区块网格对齐、断面垂直整面墙、与种子无关）。观感是「洞」而不是
> 「碎」，已由 v2.0 的逐方块碎裂场整体取代；旧判定代码仅剩一份私有拷贝保留在
> `BrokenSkyblockChunkGenerator`（老维度 `maixr:overworld_broken` 兼容老存档用，
> 常量与哈希不得改动）。旧方案的 v2~v5 弯路教训见本文末尾与 git 历史。

### 模型总览

地形破碎完全在 vanilla 密度管线内求值（自定义 DensityFunction 类型，
注册进 `Registries.DENSITY_FUNCTION_TYPE`，值类型 `MapCodec` —— 与区块生成器同款硬规则）：

```
final_density = range_choice( input=cache_2d(maixr:fracture),
                              min_inclusive=-4.0, max_exclusive=-3.999,
                              when_in_range=-4.0,                       ← 完全撕裂列短路
                              when_out_of_range=
                                min( add( 原版地形链(内层包 maixr:plate_displace),
                                          cache_2d(maixr:fracture) ),
                                     原floor ) )                        ← 现行表达式原样
                        └── 撕裂深度（负值，0=完好，-4=强制空气）┘
```

**短路语义**（2026-10-25 性能冲刺变更引入，变更 `2026-10-25-fracture-perf-leaps`）：
完全撕裂列（撕裂深度 ∈ [-4.0, -3.999)）输出常数 -4.0，跳过原版链与 noodle 的
求值；完好区与部分撕裂带走 `when_out_of_range` = 现行表达式**原样**，逐位一致。
分类安全性：原版 final_density 正峰 ~1.6 ≪ 3.999，完整路径在该区间恒负，与常数
-4 的实体/空气判定一致。epsilon=0.001 为抗浮点抖动的可读余量（离线采样实测
短路带与精确 -4.0 的面积差仅 0.01~0.12pp）。旁路（出生点掩码预筛 /
getBaseHeight / dressing）语义不受影响——掩码直接读 fracture 实例（不经 JSON
装配），高度探针按「首个非空气方块」符号判定、短路常数与完整路径同号。
**豁免边界**（用户验收口径 85% + 少数微差直接通过）：短路后同种子同坐标对比
sections 相同率 96.9%~97.3%，差异为 aquifer/装饰随机的**材质微差**（石头同族
互换、树叶 distance ±1 等），无 air↔实体翻转、无结构性形态差异；同构建两 JVM
重跑一致（确定性成立）。JFR 实测短路对墙钟无可测收益（原版链逐点部分仅占
worker ~2.7pp），保留它是行为级优化落地件而非性能项。

碎裂场是**纯 2D（xz）场**（跨区块连续、同种子确定性），由三个因子相乘：

1. **统一带进度**（v2.0 后期用户决定取消四带静滞渐变与平静区）：
   带进度恒为 `UNIFORM_BAND = 2.0`（原渐变设计碎块带外沿水平）；
   末地不再应用碎裂场（下界/末地为原版生成），无任何静滞区。
2. **脊状裂缝噪声**（带种子）：`ridge = 1-|noise|` 阈值化 —— 各向同性、
   天然分叉；**纸撕裂边缘**：脊线坐标经高频域扭曲（撕扯弯折）+ 四倍频程
   （64/32/16/8 波长毛刺）+ 阈值宽度抖动（豁口/收窄突变），线条呈
   撕纸毛边而非平滑圆弧。
3. **板块存活率**（无种子哈希只做抖动）：2D Voronoi（cell 64 格），板块按带
   死亡；死亡板块的海岸线沿抖动 Voronoi 边界延伸（不是 cell 网格直线）；
   碎屑带再乘一层 cell 8 格的碎屑子层。
4. **震中加压**（见下）：震中半径内把存活率压向地板。

### 碎裂常量（`FractureDensityFunction` 类顶部；想调手感改这里）

| 常量 | 值 | 含义 |
|---|---|---|
| `UNIFORM_BAND` | `2.0` | 全图统一带进度（用户调参；原渐变设计碎块带末水平：裂缝阈值 0.45 / 板块死亡 0.60 / 漂移 25 格 ×scale，碎屑子层关闭） |
| `CALM_RADIUS` | `0.0` | 默认静滞核心半径（主世界与下界 = 0，无平静区）。（历史：旧 `broken_end.json` 曾覆盖 300，该文件已删除，末地为原版生成） |
| `CRACK_END` | `3072.0` | 震中随机候选搜索半径基准（历史四带裂缝带外沿） |
| `TEAR_SCALE` | `4.0` | 撕裂深度满值：存活率 0 时输出 -4，任何原版密度都被压成空气 |
| `RIDGE_NORMALIZE` | `3.2` | 脊状噪声归一系数（四倍频程 + 域扭曲下模拟定值） |
| `TEAR_WARP_AMPLITUDE` | `10.0` | 纸撕裂域扭曲幅度（格）：脊线采样坐标被高频噪声拉扯的最大距离 |
| `TEAR_WIDTH_JITTER_FREQ` | `3.1` | 裂缝宽窄抖动频率（波长 ≈20 格的豁口/收窄突变） |

曲线（按带进度 t 分段线性）：`CRACK_THRESHOLD`（裂缝阈值 2.0→0.80→0.80→0.45→0.28；0.80 在 t=0.10 ≈577 格即达满 —— 历史调参：渐变时代要求离开平静区后迅速达到原 3000 格破裂水平）、
`CRACK_WIDTH`（边缘软化 0.10→0.18）、`PLATE_DEATH`（板块死亡 0→0→0.60→0.62）、
`FINE_DEATH`（碎屑子层 0→0.32）、`DRIFT_AMP`（漂移幅度 0→5→25→40）。
**阈值经 `_tools/fracture_sim.py` 体素模拟定值**（俯视/剖面图），不凭手感。

### 垂直形变：`maixr:plate_displace`

包装子 DF 按板块漂移量偏移采样坐标：水平漂移 + 垂直漂移 + 断层错位。
幅度按带 `0 / ≤5 / 15~25 / 30~40`（× 维度折算）。板块内部刚性、边界过渡带
平滑混合（过渡带即断层错位缝）。`tilt` 参数为倾斜剪切，**默认 0 = 关闭**。

安全前提（spike 实测）：本类在 JSON 里放在 `minecraft:interpolated` **内层**，
偏移采样跨过插值器时 NoiseInterpolator 对非 NoiseChunk ctx 直接下钻直算，
值正确；被引用的 vanilla density_function JSON 里没有任何 `interpolated` 标记
（已核实），不会踩插值器状态缓存。

### 材质 dressing（`MaixrDressingPass`，震中侵蚀 + 天空石结晶）

密度函数只控几何，材质靠 `BrokenOverworldChunkGenerator.applyBiomeDecoration`
**链尾**的确定性逐方块 pass（装饰完成后执行）：

| 常量 | 值 | 含义 |
|---|---|---|
| `SCULK_DENSITY` | `0.35` | 震中侵蚀：置换概率 = 加压强度 × 0.35（随距离衰减） |
| `SCULK_DEPTH` | `2` | 震中侵蚀向下最大层数 |
| `CRYSTAL_BAND` | `2.5` | 碎屑带天空石结晶起始带进度 |
| `SKY_STONE_CHANCE` | `0.08` | 碎屑带浮板表层结晶概率 |

- 幽匿置换覆盖草方块等表层（`BlockTags.DIRT` + 石系 + 沙/砂砾），跳过树冠；
- **★★★ 潜声装置禁令（spec 硬要求）**：pass 只允许放置幽匿块/幽匿脉络/天空石，
  `ALLOWED` 集合在类加载时断言不含潜声传感器/尖啸体/催化剂 ——
  世界生成不放置任何潜声装置；
- mask 采样用 `RandomState.getOrCreateNoise(maixr:crack)` —— 与密度管线**同一个
  带种子噪声实例**，侵蚀永远长在碎裂场实际算出的位置上；
- **断面裸露地层零成本成立**：碎裂只动密度，原版地表规则自动把土/石/深板岩
  剖面暴露在撕裂断面上，无需任何代码。

### ★ 实现踩坑记录

1. **乘法掩码反转空气**（runServer 实测教训）：初版输出 `[-0.3, 1]` 的乘法掩码，
   但 vanilla 实体判定是 `final_density > 0.0` —— 原版密度为**负**的区域
   （洞穴/空腔/末地外岛外围），负掩码 × 负密度 = **正密度 → 空气反转成实体**
   （实测末地外岛 29/32 实心、下界碎裂带 21/32 高于原版 11/32）。
   改为**减法撕裂**（`原密度 - 撕裂深度`）后对任意符号单调：完好处深度 0
   精确还原原版，完全撕裂处 -4 强制空气。
2. **种子注入**：自定义 DF 的 `mapAll` 必须对内部 `NoiseHolder` 调
   `visitor.visitNoise(...)` 并用带种子实例重建自身 —— 否则 `RandomState` 的
   `NoiseWiringHelper` 摸不到里面的噪声，`NormalNoise` 为 null 恒采样 0。
3. **空洞区流体陷阱**：密度 ≤0 的区域由流体选择器填充 —— aquifers 关闭时
   `y < sea_level` 全是水柱。主世界 settings 必须 `aquifers_enabled=false` 且
   `sea_level=-1000`，碎裂区才是纯虚空。

## 一点五、破碎结构（天空随机生成任何结构）

> **一句话**：「破碎」世界里，**天空（y ≥ 201）里会随机悬浮着各种结构** ——
> 村庄、前哨站、要塞、远古城市、试炼密室、末地城、热气球、星舰、模组里的飞船/神殿……
> **全部结构都能上天**，平均**每 100 个区块一座**。

### 规则

| 项 | 值 |
|---|---|
| 生效范围 | **只**在「破碎」世界类型的主世界 |
| 概率 | **1 / 100**（每区块 1%；平均每 100 区块一座） |
| 高度 | 结构**底部** y ≥ **201**，在 [201, 319-结构高度] 内随机 |
| 池子 | 服务器上**所有已注册结构**（原版 + 全部模组，自动收集，不硬编码） |

### ★★ 浮空薄板 bug 与两版修法

**症状**：世界高空随机出现**大片浮空的、只有两三格高的区块**，中间还有洞。

**根因**：Beardifier（原版的"胡须器" = **地形适配**机制）。

```java
// NoiseBasedChunkGenerator.createNoiseChunk 内部：
NoiseChunk.forChunk(chunk, randomState,
        Beardifier.forStructuresInChunk(structureManager, chunk.getPos()), ...)

// Beardifier.forStructuresInChunk 内部：
startsForStructure(chunkPos, s -> s.terrainAdaptation() != NONE)
    .forEach(start -> {
        for (StructurePiece piece : start.getPieces()) {
            if (piece.isCloseToChunk(chunkPos, 12))          // 12 格内
                add(new Rigid(piece.getBoundingBox(), terrainAdjustment, ...));
        }
    });
```

只要结构带 terrain_adaptation（村庄/前哨站都是 beard_thin），
原版就会在它周围 **12 格内按它"长地形"**。我们把结构抬到 y≥201 的虚空里 ——
Beardifier 算不出合理高度，**就地摊成两三格厚的浮空薄板**。

#### ❌ 第一版修法（已废弃）：把带地基的结构全部剔除

按 terrain_adaptation == NONE 过滤，264 个结构里只放行 175 个。
**问题：村庄、前哨站、要塞、远古城市、试炼密室全都上不了天** ——
玩家明确要求「我就要让它们上天」。

#### ✅ 第二版修法（现行）：在 BIOMES 阶段临时摘掉天空结构的 references

BrokenOverworldChunkGenerator.createBiomes：

```java
Map<Structure, LongSet> original = SkyStructurePlacer.maskSkyReferences(chunk, structureManager);
if (original == null) {
    return super.createBiomes(randomState, blender, structureManager, chunk);
}
// super.createBiomes 是异步的 → 还原必须挂 whenComplete（不能用 try/finally）
return super.createBiomes(randomState, blender, structureManager, chunk)
        .whenComplete((result, error) -> chunk.setAllReferences(original));
```

Beardifier 看不到这些结构 → **不长任何地形**；
FEATURES 阶段 references 已还原，applyBiomeDecoration 照常把结构方块放出来。

**★ 时机必须是 BIOMES，不能是 NOISE**

| 事实 | 后果 |
|---|---|
| ChunkAccess.noiseChunk **永久缓存**（if (this.noiseChunk == null)，全 jar 无人重置） | 读一次就定型 |
| 它在 **BIOMES 阶段**（ChunkGenerator.doCreateBiomes）就创建 | **比 NOISE 还早** |
| 等到 fillFromNoise 再屏蔽 | Beardifier 早读完了，**完全无效** |

**★ 为什么摘 references 是安全的（无竞态）**

| 问题 | 答案 |
|---|---|
| Beardifier 读谁的 references？ | **本区块自己的**（level.getChunk(chunkPos, STRUCTURE_REFERENCES)） |
| 邻居的 createReferences 读什么？ | 读我们的 **starts**，不读 references → 不受影响 |
| 还有谁需要本区块 references？ | 本区块的 applyBiomeDecoration（FEATURES），那时已还原 |
| 异步安全吗？ | super.createBiomes 是 supplyAsync，还原挂 whenComplete |

**★ 判据**：按 pieces 现算底面 >= MIN_Y - 4 才算天空结构
（**不能**用 StructureStart.getBoundingBox() —— 它带缓存，被 move 过之后就过期）。
同一结构类型可能既有地面实例又有天空实例，只有"这份引用解析出的 start 清一色是天空结构"时才摘。

### 实现要点

**① 走原生的 StructureStart 注册路线**（而不是自己一次性放完）

在 `createStructures` 阶段调 `structure.generate(...)` 拿到 `StructureStart`，
`move` 上天后调 `StructureManager.setStartForStructure(...)` 登记进区块。
之后**原版的引用机制自动接管**：

```
STRUCTURE_STARTS      我登记 start
STRUCTURE_REFERENCES  createReferences 扫本区块±8，把 bbox 相交的区块登记为引用
FEATURES              applyBiomeDecoration -> startsForStructure -> placeInChunk
                      每个区块只放自己那一片
```

这样**跨区块、局部放置、性能全部由原版保证** —— 不会因 `WorldGenRegion` 写半径限制而被截断。

**② ★ dry-run 安全校验（关键）**

`StructurePiece.move()` 的语义是**只移动碰撞箱**，真正方块坐标由子类自己维护：

| 类 | 同步真实坐标？ |
|---|---|
| `TemplateStructurePiece` | ✅ 更新 `templatePosition` |
| `PoolElementStructurePiece` | ✅ 更新 `position` |
| `MineshaftPieces` | ❌ 覆写了但**没同步走廊起点** |
| 未知模组 piece | ❓ 可能根本没覆写 |

所以搬移**之前**先逐个 piece 试 `move`，检查包围盒是否真的跟着动；
**任何一个不听话 → 整座结构放弃**。宁可不生成，也不要在地面留一堆搬不动的残骸。

**③ 不用 `StructureStart.getBoundingBox()` 算高度**

它会把结果**缓存**在 `cachedBoundingBox` —— 搬移后缓存就过期了。
代码里改用 `piecesBBox(pieces)` 现算。

### 为什么不需要判世界类型

`maixr:broken_overworld` 这个生成器**只被** `world_preset/broken.json` 的主世界引用，
所以"`tryPlace` 被调用"**本身就等价于**"当前是破碎世界类型的主世界"：

| 世界类型 | 主世界生成器 | 会走到这吗 |
|---|---|---|
| 默认 | `minecraft:noise` | ❌ |

## 一点七、空域浮岩（陨石团簇 + 粗矿块）

> **一句话**：天上（y=110~170）飘着的<b>不只是灰色陨石</b> ——
> **35% 陨石团簇 + 65% 各种粗矿块**。

### 为什么改

玩家反馈「天上漂浮的陨石块太多了」。原来这个 Feature **100% 只放灰色陨石**，
整片天空都是同一种暗灰色，很单调。

### 改成什么

| 种类 | 比例 | 外形 | 方块 |
|---|---|---|---|
| **陨石团簇** | 35% | 椭球 2~4 × 1~3 × 2~4 | 外壳 `ae2:sky_stone_block`（可粉碎成陨石粉）、内核 `ae2:smooth_sky_stone_block` |
| **粗矿块** | 65% | **圆球** r=2~3 | 从 16 种粗矿块里随机一种，通体填充 |

### 形状（圆润度）

方块世界里"球"必须体素化，严格按数学椭球（`d <= 1.0`）出来会有明显棱角。
所以把判定阈值**放宽**，把边缘补齐：

| 种类 | 阈值 | 半径 | 说明 |
|---|---|---|---|
| 陨石团簇 | `1.22` | 2~4，三轴接近等长 | 实测 147 块（理想球 113）——圆润但有碎石感 |
| 粗矿块 | `1.25` | 2~3，**三轴等长** | 实测 57 块（理想球 34）——饱满的小球 |

> **★ 阈值是离散跳变的**（实测）：r=3 时 1.22 → 147 块，1.25 → 171 块，1.35 → 179 块（退化成方块团）。
> 所以别凭感觉调，改之前先用体素模拟看一眼形状。

> **旧版的问题**（玩家反馈"形状太难看"）：
> - 陨石 `ry` 只有 1~3 而 `rx/rz` 是 2~4 → 出来是**压扁的饼**
> - 矿块做了"边缘随机剔除"想模拟锯齿感 → 实际是**带缺口的方块团**
> - 现在三轴接近等长 + 阈值补齐 = 圆润的球

### 密度

`placed_feature/sky_stone_cluster.json`：

```json
{ "type": "minecraft:rarity_filter", "chance": 8 }
```

`rarity_filter` 的真实语义是 `nextFloat() < 1/chance`（`RarityFilter` 源码实测），
所以 **chance=8 = 每个区块 1/8 概率**。比原来的 12 密 50% ——
因为现在 65% 是更小的粗矿块，需要更密才不显空。

### 调参

| 想改什么 | 改哪 |
|---|---|
| 陨石/矿块比例 | `SkyStoneClusterFeature.METEOR_SHARE = 0.35D` |
| 整体密度 | `placed_feature/sky_stone_cluster.json` 的 `chance` |
| 高度范围 | 同上，`height_range` 的 `min_inclusive` / `max_inclusive` |
| 加矿种 | `SkyStoneClusterFeature.RAW_ORE_IDS` 加一行 |
| 形状圆润度 | `placeBlob` 的 `1.22D`（陨石）/ `placeOreBlob` 的 `1.25D`（矿块） |

## 一点八、世界出生点选择（`BrokenSpawnSearch`）

> ⚠️ **历史注记（v2.0）**：开局空岛系统（`BrokenIslandHandler` 在 (0,160,0) 放
> `maixr:broken_skyblock` 结构、改写世界出生点、`spawnRadius=0`、复活拉回三件套）
> **已整体删除**。老存档里已放置的岛方块保留原样；`spawnRadius` 游戏规则不再被本模组触碰。
> 完整实现细节见 git 历史（`BrokenIslandHandler.java` / `BrokenIslandData.java`）。
> 空岛移除后出生点一度走原版逻辑，但统一碎裂水平（`uniformBand`）下 vanilla
> 出生点搜索的两层防线全部失效（`isFaceFull(UP)` 认可撕裂断面、121 区块全失败时
> 的兜底分支**不做任何合格性检查**直接把出生点设到可能纯虚空的位置——实测掉虚空
> 死亡），于是有了本节的出生点接管（`BrokenSpawnSearch`）。

### 合格口径（用户简化决定）

- 出生列存在**表面方块**（从上往下第一个非空气方块，纯虚空列排除）；
- 出生位（表面上方 1 格）与其上一格均为空气；
- **表面材质不限**（泥土/草方块/树叶/石头断面均可）。

> 最初口径是「表面 ∈ `BlockTags.DIRT` ∪ 树叶 + 30 格内有原木」，实测碎裂区
> 存活碎块上树木稀疏，螺旋推到 13 区块（290 个预筛命中）仍无合格列——用户决定
> 简化为「生成在正常区块即可」，木头检查与表面材质限制一并移除。

### 两段式挂点（实测教训：搜索不能放在 CreateSpawnPosition 回调里）

1. **`LevelEvent.CreateSpawnPosition`**（`setInitialSpawn` 内，区块系统尚未热身）：
   只判破碎世界并**取消 vanilla 搜索**（vanilla 的 121 区块螺旋同样会撞上慢填充），
   **绝不在这里生成区块**。
2. **`ServerStartedEvent`**（`prepareLevels` 之后、玩家可连接之前）：区块调度系统
   已全速运转，在这里跑两级搜索并写 `levelData.setSpawn`。仅新世界初始化才搜索
   （第一段设静态标记），老存档重启的 level.dat spawn 不动。

### 三级搜索（2026-10-24 性能变更）

1. **掩码离线预筛**：碎裂场纯 2D，不加载区块即可判定列有无地形——减法语义下
   「可能有地形」⟺ 存活率 > 0 ⟺ `compute > -TEAR_SCALE`（初版文档写的
   「掩码 > 0」是乘法掩码口径，减法重写后的同一语义映射）。
   区块粒度切比雪夫螺旋（r=0,1,2,…），每环先过本预筛。
2. **逐列高度场离线校验**（第二级，2026-10-24 插入）：对预筛命中区块逐列调
   vanilla 公开 API `NoiseBasedChunkGenerator#getBaseHeight(x, z, WORLD_SURFACE,
   level, randomState)`，返回 > minY 即「该列在噪声阶段存在实体」。它内部用
   一次性离线 `NoiseChunk`（`Blender.empty()`，**完全不接触区块系统、无死锁面**）
   从顶向下按真实插值管线求首个非空气方块；本模组 `aquifers_enabled=false` 且
   `sea_level=-1000`（高于 minY=-64），`Aquifer.createDisabled` 语义下
   **「非空气 ⇔ 插值后 final_density > 0」，与真实生成噪声阶段逐位一致**
   （同一 `RandomState`/噪声实例）。列扫描次序与真实校验一致（lz 外层、lx 内层），
   命中即短路。**为什么必须走这条 API**：`NoiseChunk.NoiseInterpolator.compute`
   在插值循环外按点求值会抛 `IllegalStateException`，且非 `NoiseChunk` 上下文
   会退化成未插值的 cell 函数（值不对）——拿离线 `NoiseChunk` 单点 `compute`
   final_density 的「直觉方案」两条路都死（1.21.1 反编译核验）；每列新建单 cell
   宽 `NoiseChunk(1)` 的代价是同区块 16 倍 cell 求值，但仍是毫秒级纯 CPU。
3. **真实区块校验**：离线两级预筛**都命中**的区块才 `getChunk` 全生成后逐列——
   从 `WORLD_SURFACE` 高度向下找首个非空方块（见下坑 ②），从其上向上找首个
   「连续两格空气」，合格即 `setSpawn` 并结束。找不到就继续螺旋，**不设上限、
   不退化**（int 螺旋上限 ±21 亿区块，物理上等价无限）。features（树/湖/浮岩/
   晶洞）与结构地基的离线不可见差异由这一级兜底。

### ★ 性能变更背景（2026-10-24）

> 初版两级搜索对**每个**掩码命中区块都同步 `getChunk` 整块生成（FULL 状态，
> 含 8 邻块依赖链 + features + 光照，单候选 1~2s）。当时实测「3 个随机种子
> 全部第一区块命中（2~3ms）」是假象——`prepareLevels` 恰好预生成了原点附近
> 区块，`getChunk` 直接拿现成的；玩家实际种子下原点附近大片碎裂区无合格列，
> 螺旋逐候选整块生成，**主线程阻塞约 2 分钟（TPS=0）**（玩家实测）。
> 插入第二级离线校验后，整块生成只发生在双命中候选上（预期个位数区块），
> 螺旋推进本身降为毫秒级。种子命中分布不变（离线校验只剔除、不重排）。

实测：3 个随机种子全部在**第一区块命中**（耗时 2~3ms，旧两级口径下的历史数据）。
2026-10-25 三级搜索客户端实测（整合包 0.1.3 + NeoForge 21.1.256）：新建破碎世界
原点首区块命中——预筛命中 1 / 离线命中 1 / 实际生成 1，搜索全程 **36ms**，
表面方块为模组方块「染梦草方块」（同时验证「表面材质不限」口径对模组方块成立）；
日志 `[破碎] 出生点选定：0, 118, 0（…耗时 36ms）`。旧版坏种子下分钟级阻塞的路径
（逐候选整块生成）已不复存在：真实生成只发生在离线双命中的候选区块上。

### ★ 实现踩坑记录

1. **`NoiseChunk` 的 fillArray 路径绕过 `cache_2d` 单条目缓存**：
   `NoiseChunk$Cache2D.fillArray` 直接透传给包着的函数，而 `fillAllDirectly`
   以 **y 为外层、xz 为内层**逐点遍历（4×4×16）——纯 2D 的碎裂场被同列重复
   求值 16 倍，单区块生成管线实测 fracture 被调 **~300 万次**（含 ±8 区块依赖链），
   区块填充从毫秒级劣化到秒级，`getChunk` 同步等待把启动/搜索拖到超时。
   修法：`FractureDensityFunction.compute` 加 **per-instance ThreadLocal 的
   直接映射列缓存**（必须 per-instance：下界/末地/离线掩码的同列输出不同；
   必须 ThreadLocal：worker 线程并发，保证位置↔值原子配对）。槽位按碰撞对期望
   定档（2026-10-25 变更 `2026-10-25-fracture-perf-leaps`）：每批次 ~256 列，槽位数
   N 下两列共享槽位期望 ≈ C(256,2)/N —— 256 槽 ≈ 94 对，4096 槽 ≈ 8 对；
   内存 4096×(8+8)B=64KB/线程/实例。

   **★ 槽位索引 bug（2026-10-31 修正，变更 `2026-10-31-fix-column-cache-slots`）**：
   上面的「4096 槽 ≈ 8 对」**从未成立过**。原索引写死
   `key * 0x9E3779B97F4A7C15L >>> 58`，只保留乘积累加的**高 6 位**，再与
   `CACHE_SLOTS - 1` 相与后**实际只有 64 个槽位可达**——256/4096/16384 三档
   行为完全等价，64KB 内存白付。这解释了当年「扩容后墙钟无可测变化」：
   容量从未扩大过。修法：`SLOT_SHIFT = 64 - log2(CACHE_SLOTS)`，索引改用
   `>>> SLOT_SHIFT`（容量再变也不会脱节）。修复后同机同日实测：原版 7.11s /
   破碎 **5.40s 与 5.42s**（两次全新世界），比值 **0.76×**（修复前同口径
   2.38×），已低于 1.5× 参考线。缓存语义未变（键比对 + 未命中回落
   `computeUncached`，槽位选择不影响返回值），逐块哈希验收 sections 97.14% /
   BE 99.95%，与同构建自漂移 97.70% 同水平——属值恒等优化。
   详见 `_docs/生成性能测量.md`「2026-10-31 缓存修复」节。
2. **WORLD_SURFACE 高度图比真实顶方块低**：surface rule（草方块等）写在高度图
   更新之后（generation 内部 `setBlockState` 走 `isMoved=true` 不更新高度图），
   实测 grass_block 落在 `getHeight` 返回值处。直接把 `h-1` 当表面会几乎全列
   失败（runServer 实测 196 个预筛命中区块零合格）。修法：从 `h` 向下找首个非空
   方块，再从其上向上找首个连续两格空气（对树叶覆写同样成立，出生在树冠顶）。
3. **天空结构 piece 跨度越界**：`WRITE_RADIUS_CHUNKS` 原校验只看「整体包围盒
   相对注册区块 ≤ 8」，但 `RuleProcessor.processBlock` 读取的是「**本 piece**
   模板全部方块」，超长 piece（大型 jigsaw）从中间区块放置时必然越界
   （`Requested chunk unavailable`）。修法：补一道**每个 piece 自身跨度 ≤ 8 区块**
   校验，超限整座放弃。

## 一点九、通行与伴生岛（裂缝桥 / 碎片道路网 / 伴生岛 / 悬空晶洞治理）

碎裂场把地表水撕掉、把陆地撕碎之后，「跨碎片通行」与「补给」成为玩法主瓶颈。
本节四个系统分两层：**生成期**（dressing 链尾、常开、纯本区块）做裂缝桥、伴生岛、
悬空残余清理与晶洞生成拦截；**加载期**（`ChunkEvent.Load`、配置门控）做跨碎片
道路网与大晶洞补扫。

### 裂缝桥（`CrackBridges`，生成期、常开）

- **只读本区块高度图**（`MOTION_BLOCKING_NO_LEAVES`），沿 +X/+Z 扫
  「实心 → 虚空 → 实心」裂缝直接架桥——因为全世界都是裂缝，命中必然。
- 缝宽 `MIN_GAP=2` ~ `MAX_GAP=12` 格（跨出区块的不算，保证纯本地）；两端地表
  高差 ≤ 8；只连 y ≤ 100（`MAX_Y`）的实心列；每区块 1/2 概率（`CHANCE=2`）、
  最多 `MAX_PER_CHUNK=6` 座。
- 桥面 3 格宽、沿两端高度线性插值、**只填空气**、上方清 2 格；材质按坐标 hash
  混合：3/20 苔藓石砖 + 2/20 裂纹石砖 + 其余石砖。
- 为什么纯本地：按「板块中心连线」跨区块建桥的旧方案，端点区块常未加载，
  实测尝试 1000 / 建成 0；跨区块读取在生成阶段还会直接崩服（见下道路网同款教训）。

### 碎片道路网（`FragmentRoadNetwork`，加载期、`bridgesEnabled` 默认 false）

以存活碎片（Voronoi 板块 cell）为单位的「基建」级建桥，学 RoadWeaver：

- **选边**：候选 = ±2 cell 邻域内最近的存活碎片，每碎片最多 `NEIGHBORS=5` 条；
  相对邻域图（RNG）过滤——仅当第三方碎片「同时比两端距离的 **0.8 倍**更近」才
  抑制该边（原用 < ab 判定，稠密碎片场里几乎全被抑制 → 0 建成）；全抑制时兜底
  连最近一个。每对碎片只由坐标字典序小的一方发起。
- **去重**：已建对存 pairKey 哈希进 SavedData `maixr_road_network`，跨会话不重复建。
- **路径**：A* 于 4 格网格（`GRID=4`、边界外扩 `EXPAND=20`、2 万节点上限、
  `MAX_ITER=40000`）；代价 = 步长 ×（1 + 坡度²×8），穿越实心 +6，地表 y > 180
  （`MAX_SURFACE_Y`）视为不可通行以避开天空结构；路径做邻点加权平滑。
- **竖直剖面**：坡度上限 `MAX_SLOPE=1.0`（45°）双向渐进拉平；中段正弦拱
  `BRIDGE_ARCH=3.0`（拱在端点处归零，不像直线桥那样「翘头」）。
- **桥面**：沙岩系 3 格宽（3/20 平滑沙岩 + 2/20 切制沙岩 + 其余沙岩）、只填空气、
  上方清 2 格；中线铺铁轨（`setBlock` flag 3——铁轨需要邻居更新算朝向）；
  每 6 格一个向下 3 格的沙岩桥墩。
- **端点合格三关**：真实碎片地形（±20 格 BFS 相连实心列 ≥ 60，排掉空域浮岩/
  天空结构/小岛——「通天桥」「无目标桥」的根因）；落地（脚下非空气）；
  高差 ≤ max(8, 水平距)（否则坡度不可能达标，永久失败）。
- **触发与重试**：`ChunkEvent.Load` 触发，只由「拥有碎片中心」的区块负责该碎片；
  沿线邻区块未加载 → 记入待重试队列（每维度上限 512）→ `ServerTickEvent.Post`
  每 tick 每维度补建 ≤ **4** 个碎片（A* 最坏 4 万次节点展开，限额是 tick 卡顿
  防线）；`NO_END` 类永久失败（整线无地面/两端已连）不进队列。**全程只用
  `getChunkNow` 探测，绝不强制加载**——`ChunkEvent.Load` 里再 getChunk 会
  「加载 → 事件 → 再加载」无限递归，实测把进世界拖到分钟级。
- 诊断计数器：`C_BUILT` / `C_UNLOADED` / `C_IMPOSSIBLE` / `C_NO_END` / `C_NO_PATH`
  / `C_PLATES`（排查「建成 0」时看卡在哪条闸）。

### 伴生岛（`SurfaceLakes`，生成期、常开）

大碎片内陆空地上每区块最多 1 座（岛面 y ≤ 100，玩家反馈更高的登不上），
需要 12×12（NBT 岛）或 10×10（程序岛）无地形空地，基准高度取邻列
`WORLD_SURFACE`（保证贴着碎片表面而非悬空）。类型按
`floorMod(x*7 + z*11, 100)` **确定性**分派：

| 区间 | 类型 | 内容 |
| --- | --- | --- |
| <40 | 甘蔗水岛 | 模板 `maixr:skyblock_water`（碎裂场挖掉地表水后的取水点） |
| <55 | 梦晶岛 | 模板 `maixr:skyblock_dream` |
| <67 | 末地小岛 | 模板 `maixr:skyblock_end` |
| <78 | 下界小岛 | 模板 `maixr:skyblock_nether` |
| <89 | 沙漠沙丘岛 | 程序生成：砂岩底盘 4 层逐层收窄（R=4）+ 沙层沙丘 + 仙人掌 7~10 根（高 2~4）+ 枯木 |
| 其余 | 球形水族馆 | 玻璃壳 r=5 内部充满水 + 海带 8 柱 + 珊瑚 12；**底面青金石块**（沙在悬水里会掉落） |

结构模板缺失时静默跳过（数据包异常不炸生成）。

### 悬空晶洞治理（三层防线）

1. **生成拦截**（`AmethystGeodeFeatureMixin`，治本）：mixin 打 `Feature.place`
   HEAD——`GeodeFeature` 不覆写 `place`（打子类会静默跳过，须打父类 +
   `instanceof` 过滤）；破碎世界里生成原点列向下 9 格全空气（地形已被撕掉）
   → 直接取消生成。★ mixin 类**一个字段都不能有**：SpongePowered/Mixin #576
   对 `@Unique` 字段的 STATIC 标志检查有误，处理 `@Inject` 时抛 NPE 且整个
   注入被跳过（之前晶洞一直生成的根因）。`maixr.common.mixins.json`
   `required=false` + `defaultRequire=0`，经 `neoforge.mods.toml` `[[mixins]]` 声明。
2. **生成期清理**（`VoidDebrisCleanup`，dressing 链尾、常开）：悬空岩浆按单块判
   （正下方空气即删）；晶洞族按 BFS 整坨判定（上限 `MAX_BLOB=4000`）——坨内
   任一块向下 `VOID_DEPTH=96` 格内有「非空气且非晶洞」支撑 → 整坨保留，
   否则整坨删；跨区块边界的坨一律不动。section 调色板 `maybeHas` 快路径跳过
   无关段。
3. **加载期补扫**（`geodeCleanupEnabled` 默认 false）：`VoidDebrisCleanup` 补跑
   老区块 + `GeodeBlobCleanup` 整坨上限 60000（1.21 大型晶洞外壳上万块——
   原值 6000 会整坨跳过，正是「雷霆大晶洞还在」的原因）；BFS 碰到未加载区块
   整坨放弃本次（保守不删、绝不强制加载）。晶洞族 = tag
   `maixr:void_geode_blocks`（紫水晶块/芽母/晶簇/大中小芽/方解石/平滑玄武岩）。

> **整坨判定语义（两次实机翻车）**：v1 按列判「下方 4 格全空气」→ 晶洞底部
> 下方是它自己，被拦腰切成「缺角」；v2 按列判「向下 96 格无支撑」→ 贴壁半球
> 有支撑、悬空半球没有，切成「纸杯蛋糕」。晶洞是一个球，判定必须在 **BFS
> 连通整坨** 层面做：任一块有支撑/接触地形 → 整坨留；全无 → 整坨删。

## 四、怎么检测"玩家选的是破碎世界类型"

世界类型的选择**不会直接写进 level.dat**，但**主世界用的是哪个 chunk generator 一定会被存下来**。

所以 `BrokenWorld.isBrokenWorldType(server)` 就是：

```java
return server.getLevel(Level.OVERWORLD)
        .getChunkSource().getGenerator()
        instanceof BrokenOverworldChunkGenerator;
```

这个判定既是"类型标记"也是"事实"（那个生成器真的会生成破碎地形）。

## 五、独立维度 `maixr:overworld_broken` 的现状

它是**老式**的空岛 + 95% 虚空维度（用 `BrokenSkyblockChunkGenerator`，继承 SkyblockBuilder）：

- **不再是出生地**，玩家不会自动进去 —— 「破碎」世界类型的出生点由 `BrokenSpawnSearch` 接管（见「一点八」）
- **保留**，因为老存档里已经生成过区块；结构（村庄/要塞等）在这个维度照常生成，
  只是悬在虚空里

`layers` 数组铺基岩/泥土/草方块平台）。

> `maixr:overworld_pristine` / 重生世界 `maixr:overworld_reborn` 也隶属该体系）。
> 伊甸工程已整体移除，pristine / reborn 两个维度**已不存在**，没有任何 json 引用它们。

## 六、SkyblockBuilder 全局配置（保持默认，别动）

| 文件 | 配置项 | 值 | 为什么 |
|---|---|---|---|
| `spawn.json5` | `spawnDimension` | `minecraft:overworld` | ★ 它是**全局**的，指向破碎维度会让**任何世界类型**的玩家都被拉过去（真实发生过的 bug） |
| `permissions.json5` | `forceSkyblockCheck` | `false` | ★ 开了会让 `WorldUtil.isSkyblock` 恒真，同样是全局副作用 |
| `world.json5` | `surfaceSettings` | 基岩1/泥土2/草1 | **这是 `layers` 数组写法的权威范例**（见下） |

### ★ `layers` 必须是数组，不是字符串

老式破碎维度的维度 json 里：

```json
"layers": [
  { "block": "minecraft:bedrock" },
  { "block": "minecraft:dirt", "height": 2 },
  { "block": "minecraft:grass_block" }
]
```

SkyblockBuilder 的字符串语法 `"1*minecraft:bedrock,2*minecraft:dirt,1*minecraft:grass_block"`
只有 `FlatLayers.of(String)` 走；**维度 json 的 codec 走的是 `FlatLayerConfig.CODEC.listOf()`**
（字节码实测），所以只认数组。元素形如 `{"block": "<id>", "height": <int, 默认1>}`，`extras` 可选。

> 写成字符串 → 反序列化失败 → `flatLayers.isEmpty()` → **不铺任何平台，只剩虚空**。

## 八、排查清单

> ★ **调试日志已注释**：`SkyStructurePlacer` / `SkyStoneClusterFeature` 中的
> 调试 info 输出（标记为 `// 调试输出（已注释）：`）
> 在发布前被注释掉了。排查问题时先搜 `已注释` 取消对应行，再复现。
> error / warn 级别的日志（结构放置失败、出生点异常回退）未注释，故障时仍会输出。

| 症状 | 查什么 |
|---|---|
| **进去是超平坦平台** | 主世界生成器是不是 `maixr:broken_overworld`（而不是 `maixr:broken_skyblock` —— 后者只会铺平面层） |
| **出生点不安全（碎在裂缝上）** | 出生点由 `BrokenSpawnSearch` 接管：确认日志有 `[破碎] 出生点选定`（掩码预筛 + 逐列高度场离线校验 + 真实区块校验，见「一点八」）；无日志则确认世界类型确实是「破碎」且为新建世界（仅新世界搜索）
| **离很远还是大片完整地形** | ★ 碎裂场常量是不是被改（`FractureDensityFunction.CALM_RADIUS` 等）；settings 是否指向 `maixr:broken_overworld`（地形判定**必须只看坐标**，不掺结构判断） |
| **碎裂区出现悬空水面/水体** | settings 里 `aquifers_enabled` 是否为 `false` 且 `sea_level=-1000`（密度≤0 区域会被流体选择器填水，见「实现踩坑」3） |
| **碎裂区把原版洞穴/空腔变成实体** | ★ fracture 是否被改回乘法掩码语义 —— 必须**减法撕裂**（`原密度 - 深度`），乘法会把负密度空气反转成实体（见「实现踩坑」1） |
| **村庄被虚空截断 / 末地传送门找不到** | ★ `applyBiomeDecoration` 是不是对虚空区块 `return` 了 —— 结构**就是在这里**由 `placeInChunk` 落地的，跳过它 = 半个村庄从未放置 |
| **完全没有遗迹** | 同上；另查 `createStructures` 是否被跳过 |
| **主世界不该碎也碎了** | 该存档的 level.dat 里 overworld 生成器是什么；`normal.json` 的 `replace` 是不是 `false` |
| **世界类型列表里没有"破碎"** | `normal.json` 的 `values` 是否含 `maixr:broken` |
