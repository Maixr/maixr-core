# Design

## Context

现状（见 proposal.md - Why）：`SurfaceLakes.run()` 在 `MaixrDressingPass` 链尾
（`applyBiomeDecoration` 之后）执行，单区块内一次放完、不读邻区块。当前逻辑两步：

1. 找"空地"：区块内找一块 `need × need`（NBT 岛 12、程序岛 10）区域，要求
   **所有列的高度图 `WORLD_SURFACE` 都 ≤ minY+1**（即完全没有地形）；
2. 定基准高度：从该空地左侧一列读 `WORLD_SURFACE`，只接受
   `minY+1 < h ≤ MAX_SURFACE_Y(100)` 的值，取到就贴在那个高度上生成岛。

所以小岛必然贴着碎片断崖的地表生成。约束不变：**只读本区块**、确定性、
每区块最多 1 座、模板缺失静默跳过。

## Goals / Non-Goals

**Goals:**

- 六型伴生岛统一挪到 `y ≥ 250` 的高空带，成为"往上探索"的目标
- 保持确定性（同种子同坐标结果一致）与单区块内完成
- 与天空结构（y≥201）、天隙矿脉（-50~300）共存：互不镶嵌、互不破坏

**Non-Goals:**

- 不改六型岛的内部构造、分派概率、模板内容
- 不改 `places` 触发时机 / `MaixrDressingPass` 的调用顺序
- 不做"岛与岛之间连桥"（碎片道路网只管地表碎片，不接入高空岛）
- 不给高空岛加新的方块/结构类型

## Decisions

1. **高度改为常量区间 `[ISLAND_MIN_Y, ISLAND_MAX_Y] = [250, 300]`，不用邻列地表。**
   基准高度按 `rnd.nextInt(MAX-MIN+1) + MIN` 从区块种子派生。理由：旧的"读邻列
   地表"语义在 250 以上没有意义（那里没有地形），且读高度图会得到顶部值。
   上限取 300 而非 319：水族馆球壳 r=5、球心在 `y+r`，加上海带/珊瑚最高约
   基准+13；300 留足余量，且与世界顶部保持 19 格安全距离（与 `VEIN_MAX_Y` 一致）。

2. **空判定从"高度图全空"改为"方块盒全空"。** 旧判定只问"这些列有没有地形"，
   在 250 以上恒为真（上方永远是空气），所以必须换成**真正检查目标方块盒**：
   对岛屿水平范围 × `[baseY, baseY + 岛高]` 逐块 `isEmptyBlock`。
   这样做有三个好处：① 避开天空结构（结构在 `createStructures` 阶段已落地，
   dressing 阶段读得到）；② 避开天隙矿脉（矿脉在 FEATURES 阶段已落地）；
   ③ 检查口径与最终写入口径一致，不会"以为空、写进去发现撞车"。
   代价：从 2D 高度图读变成 3D 方块读。扫描量 = 岛水平面积 × 岛高，
   NBT 岛约 12×12×16 ≈ 2300 次、水族馆约 10×10×13 ≈ 1300 次，且**只读本区块**，
   量级与既有 dressing 逐列扫描相当，可接受。

3. **岛屿高度盒取值：NBT 岛读模板 `getSize().getY()`，程序岛用固定常量。**
   沙漠岛实际最高到 `y+3`（沙丘）、水族馆球心到 `y+2r`（r=5 时 y+10）+ 海带，
   取 `PROGRAM_ISLAND_HEIGHT = 14` 作为净空盒高度——比实际最高点再多留 2 格，
   避免"顶上一格空气被占"的边界漏判。

4. **搜索顺序不变、仍每区块最多一座；密度按用户裁定降到原来的 1/4。**
   保留原来的 `oz`/`ox` 双层循环找位置、找到就 `return`。
   **频率门控**：`ISLAND_CHUNK_DENOMINATOR = 4` —— 用区块坐标的确定性哈希
   （`floorMod(hash(cp.x, cp.z), 4) != 0` 则整块跳过）决定"这个区块要不要放"，
   平均每 4 个区块 1 座。门控判据与类型分派判据（`floorMod(x*7+z*11, 100)`）
   **互相独立**：被门控跳过的区块不会改变其类型归属，同种子同坐标结果仍一致。
   弃选"降低成功后 return 的概率"：那会让净空失败与概率失败混在一起，
   实际密度随结构/矿脉占据率漂移，不可预期。
   注：v2 第一版（高空化后未降频）实际密度约每区块 1 座，明显偏高；
   1/4 是用户裁定值。

5. **不引入"岛屿下方支撑"。** 岛悬空是设计要求（旧的贴地版本靠碎片断崖的
   地表托着）。水族馆底面原本就是青金石块（防水流下坠），沙漠岛底部是逐层收窄
   的砂岩底盘，两者离开地面后视觉上都成立。**必须确认**水族馆的玻璃球壳
   下方没有水漏出：球壳本身封闭，但 `Blocks.WATER` 在无邻接水源时不会流动
   （1.21 水流更新），所以悬空水球不会漏水。

## Risks / Trade-offs

- [**取水点被搬到高空，前期补给变难**] → 这是用户明确裁定的取舍；水岛仍是
  40% 分派（占比最高），只是改成"造塔/飞行可达的探索目标"。文档与 README
  必须写清这一点，避免玩家以为是 bug
- [**与天空结构重叠导致净空失败**] → 天空结构 1/100 区块、矿脉每 4x4 区块一道，
  两者同时占据同一区块高空带的概率低；净空检测兜底，失败就跳过该区块，
  不破坏已有内容
- [**1/4 门控让实际密度低于"每 4 区块 1 座"**] → 真值 = 门控通过率 × 净空通过率。
  **实测（2026-11-01）：门控命中 25.3%、净空成功率 55%、实际含岛 14.3%**——
  净空失败的规模远超预期（起初估计 < 2%），根因是候选位共享同一个 `baseY`
  且 NBT 岛只有 3×3 个候选位。用户裁定**接受 14.3%** 并改写 spec 为
  "实际密度约 10%~15%"。若日后要更密，优先给每个候选位重抽 `baseY`
- [**3D 空盒扫描的开销**] → 单区块约 1~2 千次 `isEmptyBlock`，且命中第一个
  候选位置就 `return`；降频后 3/4 的区块在门控处直接返回，开销进一步下降。
  `/maixr bench` 复测确认
- [**NBT 模板实际高度可能大于 `getSize().getY()` 的可读范围**] →
  用模板 `getSize()` 的 Y 作为净空盒高度即模板真实高度，与放置时对齐；
  程序岛用常量 14（比实际最高点多 2 格）
- [**高空岛与 `FragmentRoadNetwork` / `FragmentBridges` 的端点判定冲突**] →
  两者都用 `MAX_SURFACE_Y = 180` 过滤"只认地表"，250 以上的岛天然被排除，
  无需额外改动；但要在文档里记录这个耦合（如果以后调高 `ISLAND_MIN_Y` 低于 180，
  就需要同步检查那两个常量）

## Migration Plan

纯世界生成内容变更，无存档迁移：旧区块保留贴地小岛（已生成即固化），新区块
出高空岛。回滚 = revert 单 commit（代码 + spec + 文档同一提交）。
实现落 `feat/broken-gen-rewrite` 分支（与 `sky-fissure-ore-veins` 同一分支）。
