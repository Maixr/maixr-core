# Design

## Context

过时表述分布在三层：OpenSpec 提示上下文（`config.yaml`，最影响后续开发）、
设计文档（`_docs/破碎世界.md`）、功能概览（README）。它们不是同一次重写的
遗漏，而是多轮迭代各自留下的：v1 渐变虚空 → v2 统一碎裂场（本会话前）、
下界/末地回退 + 出生点接管 + 通行系统（add-broken-world-gameplay，
2026-10-24 归档）。主 specs 已是最新（归档时同步并 5/5 校验通过），本次
清理把散落的叙述层拉齐到同一事实源。

## Goals / Non-Goals

**Goals:**

- 三处文件（config.yaml 上下文 / 破碎世界.md / README.md）与已同步主 spec、
  代码常量完全一致
- 每处修正可追溯到「哪次变化使它过时」（写进修正处附近的括号说明或历史注记）
- `破碎世界.md` 的未提交本地新增（179 行，出生点章节等）零丢失

**Non-Goals:**

- 不改任何 Java 代码、数据包、spec（`skip_specs: true`）
- 不重排文档结构、不统一文风——只修「事实错误」与「与现状矛盾的口径」
- 不清理代码注释（`SkyStructurePlacer` 的 band javadoc 等与代码一致，非过时）
- 不动 `_docs/玩偶接入AE2.md`（排查无相关过时表述）

## Decisions

**D1 事实源与优先级**
修正判据优先级：已同步主 specs（`openspec/specs/`）> 代码常量（逐个核对
`FractureDensityFunction` / `SkyStructurePlacer` / `MaixrConfig` 等）>
主 spec 未覆盖的实现细节（以代码为准）。两处疑点已先核实再写任务：
天空结构概率（代码保留 `band>=2.5→1/40` 与 `band<=0` 不抽签分支，但
`uniformBand` 默认 2.0 下两分支不可达 → 文档按「默认全图 1/100 + 分支
仅在调参后生效」表述）；地形阶段跳过（已删除，生成器不覆写三阶段）。

**D2 定点修正，绝不整文件重写**
`破碎世界.md` 有 179 行未提交的本地新增（出生点章节是用户写的现行内容）。
所有修正用逐处 Edit（锚定唯一旧文本），完成后 `git diff --stat` 核对行数
变化符合预期（只减不增过多）；禁止 Write 整文件。

**D3 历史注记原则**
已标「⚠️ 历史注记」的章节（渐变虚空、开局空岛、伊甸工程相关）**保留不动**
——项目文档规范要求「过时章节删除**或明确标注历史**」，这些已合规。
正文里新发现的过时表述，若其历史背景有排查价值（如「四带 300/3072/6144」
作为常量命名由来），改为「（历史：…）」内联标注而非删除。

**D4 天空结构概率口径（唯一需要跨文档统一的口径）**
统一为三句话口径：默认 `uniformBand=2.0` 下**全图 1/100**；代码保留
`band>=2.5 → 1/40` 的加密分支与 `band<=0` 的静滞分支（调参才可达）；
`CALM_RADIUS=0` 意味着不存在平静区。README 与 破碎世界.md 一点五都按此改。

**D5 修正落点的锚定方式**
tasks 里每处修正给出「章节 + 原文关键短语」，不给行号（未提交改动会使行号
漂移）；apply 时以唯一短语匹配定位。

## Risks / Trade-offs

- [定点 Edit 漏改或多改] → 每处给唯一锚定短语；收尾用关键词 grep 回归
  （「平静区」「三维度」「倒挂」「broken_nether」「末地」等仅允许出现在
  历史注记/迁移说明里）
- [把历史背景当成错误删掉] → D3 原则兜底；删改前判断该句是否仍被正文依赖
- [config.yaml 上下文还有更早期遗留（如 v1 时代的渐变表述周边）] → 任务里
  含一次全文件通读兜底，允许任务执行时发现清单外的同类表述并按同一口径修正
  （记入任务勾选说明）

## Migration Plan

纯文档修正，无迁移；回滚 = git checkout 对应文件（注意 `破碎世界.md` 的
未提交新增会一并丢失，因此 apply 前先确认该文件的未提交改动已被用户知晓——
本会话开始时它已在 git status 中）。
