# Proposal

## Why

`FractureDensityFunction` 的列缓存槽位索引写死 `key * GOLDEN >>> 58`，只保留乘积累加的
高 6 位；再与 `CACHE_SLOTS - 1` 相与后**实际只有 64 个槽位可达**。因此
`CACHE_SLOTS` 从 256 提到 4096 的那次「L1 扩容」**从未生效**——容量、64KB/线程/实例
内存全部白付，等价于一直跑在 64 槽档位。这同时解释了 2026-10-25 冲刺里「L1 扩容后
墙钟无可测变化」的困惑：不是缓存无用，是容量从未扩大。

后果是该冲刺的整条结论链被污染：`_docs/破碎世界.md`「4096 槽 ≈ 8 对碰撞、风暴消除至
1.5%」、`_docs/生成性能测量.md` 的 L1 复测与 JFR 归因、以及主 spec 里「L1+L2 后
2.38×，裁决收尾」的归档记录，描述的都是一个没有发生过的效果。修正后实测比值
从 **2.38× 降到 0.76×**（已低于 1.5× 参考线），必须如实重写这些记录。

## What Changes

- **槽位索引改为按容量派生**：新增 `SLOT_SHIFT = 64 - log2(CACHE_SLOTS)`，
  索引改用 `>>> SLOT_SHIFT`，使 4096 槽真正生效；索引仍与 `CACHE_SLOTS - 1`
  相与，容量非 2 的幂时也不会越界。
- **行为零变化**：缓存是「键比对 + 未命中回落到 `computeUncached`」的直接映射表，
  修复只改变列落到哪个槽，**不改变任何返回值**。属 spec 定义的「值恒等优化」。
- **文档更正（本次一并做）**：
  - `_docs/破碎世界.md` 实现踩坑记录 1：删除「4096 槽消除风暴」的失效归因，
    改为如实记述 bug 与修复后的实测读数；
  - `_docs/生成性能测量.md`：L1 复测节与 L2 JFR 归因节插入勘误，旧读数标注失效
    原因并保留原始数字，新增 2026-10-31 同机同日基线重采与修复后读数；
  - `openspec/specs/broken-world-type/spec.md` 的「性能不达参考线处置」场景：
    归档实例从 2.38× 更新为修复后的实测比值。
- **非目标**：不动碎裂场噪声语义、L2 `range_choice` 装配、伴生岛/天空结构/浮岩/
  裂缝桥/道路网玩法逻辑；不改 `CACHE_SLOTS` 取值；不做 JFR 重新归因（已无必要——
  比值已达标，归因不再阻塞决策）。

## Capabilities

### New Capabilities

（无——这是既有生成管线的性能修复，不引入新的能力边界。）

### Modified Capabilities

- `broken-world-type`：仅「生成性能基线」需求的**记录性内容**变化——「性能不达
  参考线的处置」场景里的归档实例（2.38× / L1+L2 结论）需要按修复后实测更正。
  需求本身（测量口径、1.5× 参考线、处置流程）不变。

## Impact

- **代码**：`FractureDensityFunction`（新增 `SLOT_SHIFT` 常量、索引一行改动、
  javadoc 记录 bug 由来）。无新增类、无 JSON 变更。
- **spec delta**：`openspec/specs/broken-world-type/spec.md` 一处场景归档记录。
- **测量**：新增同机同日基线重采（原版 7.11s / 破碎 5.40s、5.42s 两次复验），
  值恒等验收（11941 共同区块 sections 97.14%、BE 99.95%；同构建自漂移 97.70%）。
- **风险面**：极低——纯内存索引修复，不触碰求值逻辑。老存档不受影响（缓存是
  运行期结构，不落盘）。
- **发布**：版本号 2.0.0 → 2.3.1（与既有 tag 序列 v2.3.0 对齐为补丁版），
  打 tag v2.3.1 并产出 GitHub Release。
