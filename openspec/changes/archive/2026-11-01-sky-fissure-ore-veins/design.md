# Design

## Context

现状：`SkyStoneClusterFeature` 单个 Feature（NeoForge `add_features` biome
modifier 挂 `top_layer_modification` 步，生成器类型门控在代码内）。形态历史：
v2 逐体素随机剔除（不相干随机，玩家嫌丑）→ v3 恒定圆球（玩家嫌规则）→
v4 天隙矿脉（相干随机）→ v5 系列按用户实测反馈迭代（v5.1 修纯平面、v5.2 去
支脉、v5.3 双向铺开修"太短"、v5.4 楔形收尖修"两头不够尖"）。单区块架构下
矿脉长度被 FEATURES 可写范围物理钳死在 ~65 格，用户裁定**移除区块生成限制**
（v6）。

教训：**不相干随机（逐块剔除）出毛刺团，恒定形状出规则球，中间地带要用
相干随机**（形状沿程渐变，不逐块抖）。

约束：feature 阶段执行，不触碎裂场热路径（性能基线见本轮重采值——
旧 2.38x 口径已作废，缓存修复后实测 0.76x）；`isEmptyBlock`
守卫必须保留；`broken-world-type` spec「空域浮岩」需求与 `_docs/破碎世界.md`
一点七是现行契约，改行为先改 spec。

## Goals / Non-Goals

**Goals:**

- 裂痕感四要素落地：直中轴、厚薄呼吸（扁椭球截面）、两侧挂屑、偶发错台 +
  端头楔形收尖（v5.2 裁定去掉支脉——单一笔直主脉更干净）
- **矿脉长度摆脱单区块限制（v6）**：单元网格确定性几何 + 跨区块协作放置，
  长 96~224 格跨约 6~14 区块无缝拼合
- 矿脉原版化：石中藏矿（矿石方块矿囊），**每囊独立抽矿种**、稀有度加权
  （同一条石脉混生多种矿石）
- **单体系化（v7）**：陨石球删除，天空石成为矿脉的第三种宿主，只在高空出现；
  宿主由 origin y 分带决定，深板岩区不再出石脉
- 确定性：矿脉几何、宿主分带与天空石抽取全部由「世界种子+单元坐标」派生，
  与区块求值顺序无关，写入幂等；不再有任何 `ctx.random()` 的形态随机
- 参数集中成命名常量，延续"想改手感改一个数"的调参风格

**Non-Goals:**

- 不做"按周围实际地形材质调宿主"（feature 阶段不能跨区块读地形，且会破坏
  跨区块确定性）
- 不动挂载方式 / biome modifier / placed_feature 的 trigger 结构
- 不改碎裂场 / 地表矿石；不引入 `maixr` 自有方块类型（天空石来自 AE2）
- 不做矿脉的分叉/交叉语义（相邻单元矿脉自然交叠即可，`isEmptyBlock` 守卫兜底）

## Decisions

1. **单元网格 + 每区块协作放置（v6 核心决策，v7 沿用）**。替代"单 Feature 一次画完"：
   世界按 4x4 区块（64 格）划单元，每单元一道矿脉；矿脉全部几何由
   「世界种子 + 单元坐标」经 `WorldgenRandom.setLargeFeatureSeed` 确定性回放
   （`buildVein` 纯函数，零副作用）；每个区块扫描周围几圈单元（包围盒粗筛），
   只把落在本区块可写范围内的节点/挂屑/矿囊放下（`placeVeinSegments`）。
   选 4x4 的理由：64 格单元 ≈ 旧密度（1/16 区块）且矿脉（96~224）远超单元尺寸，
   跨区块拼合是常态而非特例。弃选的替代：① 继续单区块内做长（物理上限 ~65 格）；
   ② 结构系统（StructurePiece）承载矿脉——重量级，且矿脉是"散布地貌"不是"遗迹"。

2. **相干形状 = 直中轴 + 半径呼吸 + 附着挂屑 + 楔形收尖**。中轴方向扰动
   ±5~15°（用户裁定"笔直一些"）；截面为**扁椭球**（水平 2~4、垂直约七成，
   v5.1 修复纯平面 bug）；半径沿程 4~8 步一段渐变（不逐块抖）；挂屑是**附着**
   （径旁加 1~3 格小碎片，四向含上下，上缘不塌平），不是剔除（v2 教训）；
   错台 ~5%/步 ±1 格；端头楔形收尖：楔长 = baseR+2~3 步，半径逐级
   0,0,1,2,…,baseR 不跳级、末端单块须尖（v5.4 修复钝头）。

3. **写入边距是"片段路由窗口"而非"长度上限"（v6 重新定位；v6.2 补读操作教训）**。
   边距实证结论不变：FEATURES 可写中心区块 ±1 区块（`blockStateWriteRadius(1)`，
   单位是区块）。越界后果分两种：**写**（`setBlock`）= 静默丢块；**读**
   （`getBlockState`/`isEmptyBlock`）= 直接抛 `IllegalStateException`。
   因此 `canPlace` 按**先算术范围检查、后世界查询**的顺序实现（`[base-16,
   base+31]`，base = origin 所在区块世界坐标）——顺序反了远端节点一查就炸穿
   装饰阶段（v6.1 实测 bug：全图不生成）。生成器层原"越界读防线"
   catch(RuntimeException) 已按需求移除，异常 fail fast 不再静默吞。

4. **跨区块一致性的三个支点**：① 几何纯函数（单元 RNG 与求值区块无关，
   `veinOrigin` 独立序列支撑包围盒粗筛不污染主序列）；② 写入幂等（只进空气、
   状态恒定，区块先后顺序无关）；③ 矿囊归属按区块（`placed` 集只记本区块
   本次已放的宿主，矿囊只换这些——每块矿石由拥有它的区块放置，不会重复或遗漏）。

5. **矿囊锚点沿径采样**：每脉 6~14 处（v6 长脉加量）、r=1~3，只替换已放宿主。
   **每个矿囊独立抽矿种**（v6.3，用户需求"允许多种矿石生成在同个石脉上"），
   权重表集中常量：原版铁/铜各 20、金 8、钻石 3；模组矿默认 8、稀有
   （铀/钠夸达/钛/钨等）4。矿囊写入用 `inWindow`（纯算术窗口）而非 `canPlace`——
   宿主方块此时已非空气，`canPlace` 的 `isEmptyBlock` 会恒 false 导致矿石永不
   生成（v6.3 修的 bug）。不剔除表面矿（原版有 air-exposure 剔除，浮岩小、
   剔除浪费且露头是主要发现途径——可发现性优先）。

6. **矿池显式映射表**：`RAW_ORE_IDS` 16 项逐条映射为矿石方块 id
   （`minecraft:raw_iron_block`→`minecraft:iron_ore` 等），registry 过滤
   机制保留。无对应矿石方块的候选（如 `enderio_evolution:crude_steel_block`）
   直接剔除并在 javadoc 记录原因——不为凑数放错方块。

7. **宿主按 origin y 分带，整脉统一（v7 替换 v6 的 70/30 随机）**。
   分带规则（常量，可调）：

   | origin y | 宿主 | 常量 |
   |---|---|---|
   | `VEIN_MIN_Y(-50) ≤ y ≤ DEEPSLATE_ZONE_MAX_Y(8)` | `minecraft:deepslate` 100% | — |
   | `8 < y < SKY_STONE_MIN_Y(180)` | `minecraft:stone` 100% | — |
   | `180 ≤ y ≤ VEIN_MAX_Y(300)` | `stone` 85% / `ae2:sky_stone_block` 15% | `SKY_STONE_SHARE = 0.15D` |

   选 origin y 而非"每节点按自身 y 判定"的理由：① 整脉一族群不混拼（v6 已有
   约束"不出现族群混拼"）；② origin y 是单元种子直接产出的量，判定点唯一，
   跨区块回放必然一致；③ 若逐节点判定，一条竖直游走的矿脉会在 y=8 与 y=180
   处被切成两种材质，视觉上像"接缝"，且矿囊变体选择要在每囊处重复判定。
   代价：竖直轻摆 ±3 会让少数方块越过带边界（y=5 的脉底部可能到 y=2 仍是深板岩，
   或 y=182 的脉顶到 y=185 仍是天空石）——这是刻意的，边界处有 3 格模糊比硬切更自然。

   弃选"按周围实际地形材质"：feature 阶段读相邻区块方块会抛
   `IllegalStateException`（v6.2 教训），只读本区块也不足以覆盖 ±112 格的矿脉
   跨度；而"地形材质"本身在破碎世界里被撕裂得七零八落，按高度带才是稳定语义。

8. **天空石 = 矿脉宿主，不是独立装饰（v7）**。删除 `placeBlob` 与陨石抽取后，
   天空石只通过矿脉出现，因此：
   - 形态从"圆球"变成"细长裂隙脉"——与粗矿块→矿脉的演化方向一致；
   - 仍是 `ae2:sky_stone_block`（可粉碎成陨石粉），AE2 玩法供给不断；
   - 内核 `ae2:smooth_sky_stone_block` 不再使用（矿脉是单材质宿主 + 矿囊）；
   - 若 AE2 未安装（`BuiltInRegistries.BLOCK` 查不到该 id），该脉**回退
     `minecraft:stone`**，而不是整条不生成——保持"每单元一道"的密度契约。
   - 天空石脉的矿囊仍走常规矿石池（不引入"天空石专属矿种"）：保持
     "矿脉 = 石头 + 矿石"的统一机制，玩家在天空石脉里也能挖到铁铜金。

9. **高度上限抬到 300**：`VEIN_MAX_Y` 170 → 300。世界 `min_y=-64`、高度 384
   （顶部 y=319），300 留 19 格余量避免矿脉顶部（垂直半径最大 3 + 挂屑）越界。
   天际结构从 y≥201 起，两者在 201~300 重叠——**结构方块先于 FEATURES 阶段
   落地**，矿脉只写空气，因此不会覆盖结构，只会在结构周围的空气里共生。

10. **命名保留**：类名 `SkyStoneClusterFeature` 与注册 id
    `maixr:sky_stone_cluster` 不改（存档、biome modifier、placed_feature、
    configured_feature 全部引用该 id）；只把已经没有陨石语义的
    `isMeteorAllowed` 改名为 `isVeinAllowed`。文档里注明"sky_stone"是历史名。

## Risks / Trade-offs

- [跨区块拼合出错（缺段/断面/重复）] → 三个支点对冲（决策 4）：几何纯函数 +
  写入幂等 + 矿囊按区块归属；验收以 spec「矿脉跨区块无缝拼合」场景为准
- [每区块固定成本：包围盒粗筛 + 命中单元几何回放] → 粗筛 O(1) 比较、绝大多数
  单元直接跳过；命中的回放是 O(长度) 算术与少量对象，无 IO。`VEIN_MAX_Y`
  抬高不增加回放量（几何与 y 无关），只改变 origin y 采样范围。bench 复测确认
- [单元网格密度观感] → 可调常量：`CELL_CHUNKS`（网格粗细）/
  `FISSURE_MIN~MAX_LEN`（长度）
- [直中轴 + 呼吸仍显呆板] → 挂屑密度与错台概率是独立常量，观测后可调
- [模组矿映射缺项导致矿种变少] → 剔除 + javadoc 记录；矿池日志
  （`矿脉矿池：N/M 种可用`）核对
- [**AE2 天空石供给暴涨**] → 旧陨石单颗约 100~150 块，单条矿脉上千块；
  用 `SKY_STONE_SHARE = 0.15` 把天空石脉压到约 1/7，并靠"高空带内每 16 区块
  才一道脉"再稀释一次。观测后可下调到 0.10
- [**分带硬边**] → 边界只有 3 格垂直轻摆的模糊，不做渐变混合（混合会让
  "深板岩区"语义变糊，玩家难以建立"往下挖是深板岩矿"的预期）
- [已生成区块不回溯] → 旧存档里既有陨石球与随机宿主矿脉保留原样，新区块按
  新规则生成（与既有 dressing 内容同惯例）
- [同种子确定性抽查口径] → 单元种子使确定性比旧版更强（不依赖区块求值序）；
  抽查仍按 `_tools/mca_blockhash.py` 口径

## Migration Plan

纯世界生成内容变更，无存档迁移：旧区块保留旧形态（已生成即固化），新区块出
分带宿主矿脉。回滚 = revert 单 commit（代码 + JSON + spec + 文档同一提交）。
实现落 `feat/broken-gen-rewrite` 分支。
